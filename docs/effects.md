# Эффекты и переходы — упрощение

> Статус: **предложение к обсуждению** (ревью эффектов от автора). Ничего ещё не в коде.
> Смежное: [tasks.md](tasks.md) блок 3 (текущие эффекты), [camera.md](camera.md),
> [architecture.md](architecture.md) (объекты, стейт-машина), `system.js` (деко-масштаб).

## Что сейчас и что болит

- **Звёздное небо** (`CreateStarfield`, `objects.js`) — 180 кубов-объектов на оболочке
  R≈7500, `main.js` **каждый кадр** пересчитывает `p = basePos + camEyePos` и рисует их
  до `ctx.objects`. 180 аплоадов мешей, 180 draw-call'ов, ручной ре-центринг.
- **Гиперпрыжок** (`hyperjump_state.js`) — 34 объекта `GenRingOfCubes(34,…)` (кольцо из
  34 кубов), каждый кадр: сдвиг `d`, пересчёт `Rainbow(hue)`, `color`, изгиб `bx/by`.
  Отдельный стейт.
- **Локальный перелёт** (`system_travel_state.js`) — 90 спарков-кубов с
  `scale = [12,0.2,0.2]` (массив!), корабль «поворачивается» хаком `RotY(o.base, yaw)` по
  позициям кубиков (у объектов нет вращения). Отдельный стейт. Едет деко-система `vFrom→vTo`.
- **Матрица объекта** — только `Mat4TranslateScale(p, scale)`; вращения нет, поэтому
  `system_travel` вертит корабль пересчётом точек. В `gl.js` уже висит `TODO` — убрать ветку
  `scale.length ? scale[0] : scale` (нужна только спаркам).

Итог: два почти одинаковых транзит-стейта, спец-меши под каждый эффект, хак вместо вращения,
ре-центринг скайбокса.

## Цель

Один транзит-путь, единая матрица объекта с вращением, звёзды и тоннель — из
**переиспользуемых** генераторов, покраска один раз. «Обычный корабль, обычное пространство»
всегда на экране; эффект = интерполяция позиции системы за край кадра.

---

## 1. Единая матрица объекта (+ вращение по Y)

`Mat4TranslateScale(p, scale)` → **`Mat4Model(p, scale, rotY = 0)`** (translate · Rot Y ·
uniform-scale). `CreateMeshObject.render()`:
`Mat4Multiply(viewProj, Mat4Model(this.p, this.scale, this.rotY || 0))`.

- `rotY` не задан → 0 → матрица байт-в-байт прежняя, все существующие объекты не трогаем.
- Новое: `obj.rotY = angle` — вращает объект. `system_travel`-хак `RotY(o.base, yaw)`
  уходит: у модели корабля просто `rotY`, лерпится к курсу.
- Ветку `scale.length ? …` **убрать** — только равномерный `scale`-число. Единственный
  массивный `scale` — спарк-полоски (`[12,0.2,0.2]`); после §4 спарков нет, ветка не нужна.
  (Если позже понадобится вытянутый бокс — отдельный генератор меша, не спец-скейл.)

Байт: ~0 (одна `Ms`/`Mc` + 4 умножения в `Mat4Model`, минус ветка `.length`).

## 2. Кнопка поворота корабля

Нижняя кнопка в `ship_state` («Rotate» / стрелка) — крутит `shipYaw` шагами (или держит
вращение). Объекты модели корабля несут `rotY`, лерпятся к `shipYaw`. Использует §1, новых
виджетов не вводит (та же `.button`).

## 3. Звёздное небо — один меш, без ре-центринга

- N мелких **низкодетальных сфер** (`GenSphereMesh(2,3)` или кубы — что дешевле по
  треугольникам) со случайными позициями, **нормализованными на радиус R**, штампуются в
  **один** `{positions,normals,indices}` (в `MeshGen` добавить приём готового меша, или
  просто конкатенация массивов).
- Один `CreateMeshObject` в origin, `scale = R` (R ≈ 9000, дальше всех деко-орбит).
  Рисуется как обычный объект. **`basePos` и цикл ре-центринга в `main.js` — удалить**: на
  R≈9000 против пробега камеры в деко (~сотни юнитов) параллакс — доли градуса, не видно.
- Байт: − цикл в `main.js`, − `basePos`, − 179 объектов; + один генератор-конкатенатор.

## 4. Один генератор кольца

**`GenRing(segments, rInner, rOuter, depth = 0)`** — аннулюс в XY (два кольца вершин), при
`depth>0` — короткая стенка-труба. Заменяет:

- `GenRingMesh(seg, thk)` → `GenRing(seg, 1 - thk, 1)` (орбитная линия).
- `GenRingOfCubes` — больше не нужен (тоннель — из `GenRing`, см. §5).

## 5. Тоннель гиперпрыжка — кольца на ребре

- K колец `GenRing(24, 1.9, 2.1, 0.3)`, поставленных **на ребро вдоль оси Z** поворотом
  **матрицы генератора** при создании (`g.xf` в штамповке) — или каждое кольцо отдельный
  `CreateMeshObject` с `rotY`/позицией по Z.
- **Покраска — один раз при создании**: `ring.color = Rainbow(z_along_tube)`. Больше не
  перекрашивать (сейчас `hyperjump` пересчитывает цвет каждого кольца каждый кадр).
- По сути длинная **труба**: появляется издалека по Z, едет на камеру, пролетает —
  прибыли. K объектов, K покрасок при `OnEnter`, в кадре только сдвиг по Z.

## 6. Слить транзит-стейты

Удалить `hyperjump_state.js` + `system_travel_state.js` → один **`CreateTravelState(onDone,
opts)`**:

- всегда: настоящий корабль (`CreateShipModelObjects`) + деко-система (`DecoSystem`), камера
  — 3-фазный подхват как сейчас.
- эффект = интерполяция оффсета деко-системы от `vFrom` **за пределы фрустума** и (на
  прибытии) с дальней стороны к `vTo`. `system_travel` уже делает слайд `vFrom→vTo` —
  обобщаем: середина пути = «система ушла с экрана».
- `opts.hyper` → добавляет трубу из §5 + длиннее слайд + камера на оси. Без него (локальный
  хоп) — просто слайд, без спарков (или лёгкий цвет).
- `opts.fromBody / toBody` — как сейчас.

Плюс: один код-путь, «корабль + пространство всегда видны» получается само.

## Прогресс

- ✅ **§1 матрица объекта** — `Mat4TranslateScale` → `Mat4Model(p, scale, rotY = 0)`
  (translate · RotY · scale), поле `obj.rotY` (0 по умолчанию → матрица байт-в-байт прежняя).
  `+41 Б`.
- ✅ **§3 звёздное небо** — один меш кубиков через `MeshGen`, `main.js` ставит
  `starfield.p = camEyePos` (1 присваивание вместо 180-объектного цикла), `basePos` убран.
  180 объектов/аплоадов/draw-call → 1. Байт ~0, но перф-упрощение по сути.
- ✅ мёртвое: `CUBE_QUADS` / `addCube` удалены (куб штампуется из `CUBE_MESH`).
- ⬜ §2 кнопка поворота, §4 `GenRing`, §5 тоннель из колец, §6 слияние транзит-стейтов.

Решения (подтверждено автором): §1 — `obj.rotY` opt-in; §6 — отдельный `CreateTravelState`.

## Открытые вопросы

- **A. Матрица объекта:** добавить `obj.rotY` (opt-in, существующий код не трогаем) —
  **или** полноценная `obj.mat`, которую каждый вызов строит сам (максимально «единообразно»,
  но миграция всех фабрик). Рекомендация — `rotY`.
- **B. Слитый транзит:** отдельный `CreateTravelState` (стейт остаётся, параметры выбирают
  локальный/гипер) — **или** под-режим внутри `ship_state` (больше ничего не переключаем, но
  `ship_state` и так самый крупный файл). Рекомендация — отдельный стейт.
- **C. Тоннель:** K объектов-колец с `rotY`/Z-позицией (проще) — **или** одна труба-меш
  целиком (тогда для градиента нужен атрибут цвета вершин, правка шейдера). Автор сказал
  «покрасить один раз» → скорее K объектов.
