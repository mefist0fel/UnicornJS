# Сборка и бюджет размера

Бюджет: **zip-архив релиза ≤ 13 312 байт** (правило js13k). Сборка автоматизирована одним
Python-скриптом; минификация делается локально установленным `google-closure-compiler`
(npm-пакет), без ручного похода на внешний сайт.

## Почему Python-скрипт, а не node.js-таск-раннер

Оркестрация пайплайна (конкатенация → минификация → сборка HTML → zip → копирование) —
по-прежнему `python html/packed/build.py`, не npm-скрипт. Не по идеологическим причинам: сам
`google-closure-compiler` — npm-пакет и требует node.js, он уже используется как внешний
инструмент, который просто дёргается через `subprocess`. Но заводить ради этого
`package.json`/`node_modules`/лок-файлы под сам оркестратор — не нужно, когда 80-строчный
Python-скрипт (stdlib, уже есть в системе) делает то же самое без лишней инфраструктуры.
Если для какого-то будущего шага понадобится npm-пакет, которого нет в системе — это сигнал
остановиться и оценить, оправдан ли он, а не сигнал переезжать на node целиком.

## Требования

- Python 3 (stdlib, ничего доустанавливать не нужно).
- `google-closure-compiler`, установлен глобально: `npm install -g google-closure-compiler`
  (уже стоит в системе разработки; `build.py` ищет его на `PATH` и падает с понятной ошибкой,
  если не находит).

## Этапы

1. **Разработка** — просто открыть `html/index.html`. Файлы `html/js/*.js` подключены
   отдельными `<script src>` в порядке зависимостей (см. [architecture.md](architecture.md)),
   сборка не нужна.

2. **Полный цикл** — `python html/packed/build.py`:
   - парсит `html/index.html`, вытаскивает список `<script src="js/....js">` **в том порядке,
     в котором они там перечислены** — это единственный manifest, второй раз файлы нигде не
     перечисляются;
   - склеивает содержимое этих файлов в `html/packed/bundle.js`;
   - **в релизной ветке** меняет `const DEBUG = true` → `const DEBUG = !1` в склеенном
     бандле (падает, если строка не ровно одна) — closure DCE-ит все `if (DEBUG) …` блоки
     (дебаг-меню, спавн врагов, превью-переходы) и `debug.js` целиком. `--skip-minify` этого
     не делает, поэтому в dev / `index.dev.html` дебаг-меню на месте;
   - минифицирует бандл локальным `google-closure-compiler -O ADVANCED` (через `subprocess`) в
     `html/packed/bundle.min.js` — падает с полным выводом компилятора, если тот вернул
     ошибку; предупреждения печатаются, но не останавливают сборку. **Сейчас сборка
     warning-clean** (0 warnings) — любое новое предупреждение в выводе `build.py` значит
     регресс, чинить сразу (типовые: необязательный аргумент без `= default` →
     `JSC_WRONG_ARGUMENT_COUNT`/`JSC_OPTIONAL_ARG_AT_END`; `for..in` по массиву → `+k`);
   - собирает финальный `html/packed/index.html` — тот же HTML-шаблон, но вместо набора
     `<script src>` один инлайновый `<script>` с минифицированным кодом;
   - зипует его (`zipfile`, `ZIP_DEFLATED`, максимальное сжатие) **в двух местах**:
     `html/packed/game.zip` (рядом со скриптом сборки) и `dist/game.zip` (результирующая папка
     релиза) — это одна и та же сборка, просто с копией под рукой там же, где сам пайплайн;
   - печатает размер зипа и остаток бюджета (`13312 - size`). Если бюджет превышен —
     скрипт завершается с ненулевым кодом.

3. **Быстрая проверка без минификации** — `python html/packed/build.py --skip-minify`:
   тот же конкатенированный `bundle.js`, инлайненный в `html/packed/index.html` как есть, без
   вызова компилятора и без zip.

4. **`html/packed/index.dev.html`** — пишется **при каждой** сборке (и обычной, и
   `--skip-minify`): та же страница, что и релиз, но с **неминифицированными** исходниками
   инлайном.

5. **`html/packed/build_log.md`** — история размеров: `build.py` **дополняет** его одной
   строкой на каждую **релизную** сборку (не `--skip-minify`) — дата, размер `bundle.min.js`,
   `index.html`, `game.zip`, остаток до лимита (разрядность через пробел). Создаётся с
   шапкой-таблицей, если ещё нет. В `.gitignore` (локальный трек, не коммитится). Открывать её, когда «минифицированная версия не работает, а ошибку не видно» —
   стек будет с исходными именами, а не с манглеными. Баги режима `ADVANCED` (см. ниже) видны
   **только** в `index.html`, а `index.dev.html` даёт читаемый трейс той же логики. В git не
   коммитится.

## Грабли closure `-O ADVANCED`: динамический доступ к литеральным ключам

`ADVANCED` **переименовывает ключи объектных литералов** (`{name:…}` → `{a:…}`). Если по
такому объекту потом идёт **динамический** доступ строкой — `foo[someStringVar]` — строка не
переименовывается, ключ переименован → `undefined`. Работает в dev, падает в релизе.

**Правило:** словарь со строковым динамическим доступом — либо ключи **в кавычках**
(`{ 'a': {…} }`, closure их не трогает), либо, если ключи и так перечислимы, **числовые
константы** как ключ и индекс (`const MOD_X = 0; MODULES[MOD_X]`; closure инлайнит число, а
числовой ключ не манглит) — это ещё и короче.

Сейчас так сделаны игровые словари: **`MODULES`** — числовые ключи `MOD_*` (id модуля = число,
объявлены в столбик в `modules.js`; имена полные, экономить на них смысла нет — closure их
всё равно инлайнит); **`FIRE_COLORS`** / **`SHIP_PROJ_SPEED`** / **`SHOOT_SFX`** — просто
массивы, индекс = `F_KIN`/`F_PLA`/`F_ROC` (0/1/2). Кавычки на ключах игровых словарей больше
не нужны. Остаются закавыченными только настоящие строковые словари, если появятся.

Объекты со **статическим** доступом (`Sfx.click()`, `objLoc.aPos`) кавычек не требуют —
closure переименует определение и обращение согласованно. Массивы (`ENEMY_ARCHETYPES[i]`) и
рантайм-словари (`var cache = {}`) — вне проблемы.

> **Побочная грабля числовых enum'ов:** `F_KIN = 0` → `if (m.fireKind)` ломается (0 ложно).
> Проверки наличия — `m.fireKind != null`, не на истинность. См. `PlayerTurrets`,
> `shipVizColor`, `updateCombat` в `modules.js`/`ship_state.js`.

## Инварианты

- `html/packed/bundle.js`, `html/packed/bundle.min.js`, `html/packed/index.html`,
  `html/packed/index.dev.html`, `html/packed/build_log.md` и `html/packed/game.zip` —
  сгенерированные файлы, в git не коммитятся (см. `.gitignore`). `dist/` — тоже.
- **Проверять именно `html/packed/index.html`** (минифицированный), а не только dev-версию:
  часть багов (`ADVANCED`, см. грабли выше) есть только там. `index.dev.html` — для чтения
  трейса, не замена проверки релиза.
- HTML-шаблон (стили, `<canvas>`, `#ui`) не дублируется между dev и packed версией — и
  `build.py`, и ручная разработка используют один и тот же `html/index.html` как источник
  разметки; packed-версия отличается только тем, что блок `<script src>` заменён на один
  инлайновый `<script>`.
- Минификатор вызывается на уже склеенном `bundle.js` одним файлом, а не на списке исходников
  по отдельности — так `build.py` остаётся единственным местом, где перечислены файлы сборки
  (см. [architecture.md](architecture.md)); заводить второй список файлов специально под
  компилятор означало бы держать два манифеста в синхроне вручную.
- Если размер зип-архива начинает подбираться к лимиту — сначала смотреть на ассеты
  (шрифты/текстуры/аудио — их пока нет вообще, см. [concept.md](concept.md)), потом на JS.
  Убирать читаемость кода (короткие имена, отказ от абстракций) — то, ради чего вообще выбран
  этот стиль организации кода, см. [architecture.md](architecture.md).
