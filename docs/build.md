# Сборка и бюджет размера

Бюджет: **zip-архив релиза ≤ 13 312 байт** (правило js13k). Пайплайн намеренно простой и
без node.js/npm — только Python (стандартная библиотека, без установки пакетов), как в
прошлый раз: склейка файлов скриптом + минификация внешним веб-сервисом (это устраивало
раньше, менять не стали, просто убрали bash в пользу Python и добавили упаковку в zip с
отчётом по размеру).

## Почему не node.js

Не по идеологическим причинам — просто чтобы не тащить `node_modules`/`package.json`/лок-файлы
ради одного скрипта на 50 строк. Python 3 (stdlib) или .NET script — уже есть в системе,
ничего ставить не нужно. Если для какого-то шага понадобится пакет, которого нет в stdlib —
это сигнал остановиться и сделать проще, а не сигнал ставить пакет.

## Этапы

1. **Разработка** — просто открыть `html/index.html`. Файлы `html/js/*.js` подключены
   отдельными `<script src>` в порядке зависимостей (см. [architecture.md](architecture.md)),
   сборка не нужна.

2. **Конкатенация** — `python html/packed/build.py`:
   - парсит `html/index.html`, вытаскивает список `<script src="js/....js">` **в том порядке,
     в котором они там перечислены** — это единственный manifest, второй раз файлы нигде не
     перечисляются;
   - склеивает содержимое этих файлов в `html/packed/bundle.js`;
   - собирает `html/packed/index.html` — тот же HTML-шаблон, но вместо набора `<script src>`
     — один инлайновый `<script>` с содержимым `bundle.js` (пока неминифицированным). Это
     промежуточный, но полностью рабочий билд — им можно проверить, что конкатенация ничего
     не сломала, до похода к минификатору.

3. **Минификация — вручную, внешним сервисом.** Открыть `html/packed/bundle.js`, скормить
   любому онлайн JS-минификатору (Closure Compiler service, Terser playground и т.п.),
   результат сохранить как `html/packed/bundle.min.js`. Это осознанно ручной шаг — раньше
   работало, специальной автоматизации/интеграции не требуется, а поведение разных
   минификаторов на конкретном сервисе стоит проверять глазами перед сдачей.

4. **Финальная упаковка** — `python html/packed/build.py --pack`:
   - берёт `html/packed/bundle.min.js` (если его нет — падает с понятной ошибкой, шаг 3
     обязателен);
   - собирает финальный `html/packed/index.html` с инлайновым минифицированным скриптом;
   - зипует его в `dist/game.zip` (`zipfile`, `ZIP_DEFLATED`, максимальное сжатие);
   - печатает размер зипа и остаток бюджета (`13312 - size`). Если бюджет превышен —
     скрипт завершается с ненулевым кодом.

## Инварианты

- `html/packed/bundle.js` и `html/packed/bundle.min.js` — сгенерированные/промежуточные
  файлы, в git не коммитятся (см. `.gitignore`). `dist/` — тоже.
- HTML-шаблон (стили, `<canvas>`, `#ui`) не дублируется между dev и packed версией — и
  `build.py`, и ручная разработка используют один и тот же `html/index.html` как источник
  разметки; packed-версия отличается только тем, что блок `<script src>` заменён на один
  инлайновый `<script>`.
- Если размер зип-архива начинает подбираться к лимиту — сначала смотреть на ассеты
  (шрифты/текстуры/аудио — их пока нет вообще, см. [concept.md](concept.md)), потом на JS.
  Убирать читаемость кода (короткие имена, отказ от абстракций) — то, ради чего вообще выбран
  этот стиль организации кода, см. [architecture.md](architecture.md).
