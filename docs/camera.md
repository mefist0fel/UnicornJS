# Орбитальная камера

Одна и та же камера используется во всех 3D-сценах (`html/js/camera.js`), но с разными
**ограничителями** (constraints) на сцену — это единственное, что меняется между "солнечной
системой" и "планетой".

## Модель

Камера всегда смотрит на `target` (обычно `[0,0,0]`) и задаётся сферическими координатами
вокруг него:

- `theta` — азимут (вращение вокруг вертикальной оси), радианы;
- `phi` — полярный угол от верха (0 = смотрим строго сверху вниз, `PI` = снизу вверх,
  `PI/2` = сбоку, на уровне экватора);
- `radius` — дистанция до `target` (зум).

```
eye.x = target.x + radius * sin(phi) * cos(theta)
eye.y = target.y + radius * cos(phi)
eye.z = target.z + radius * sin(phi) * sin(theta)
```

View-матрица строится обычным `lookAt(eye, target, worldUp)`. Projection — обычная
перспектива (`fov`, `aspect`, `near`, `far`).

## Ограничители — разные на сцену

`CreateCamera()` хранит `constraints = { minPhi, maxPhi, minRadius, maxRadius }` (азимут
`theta` не ограничивается ни в одной из сцен — вращение вокруг вертикали свободное всегда).
`SetCameraConstraints(c)` вызывается из `setState` при входе в сцену.

- **Солнечная система** — верхняя полусфера: `minPhi = 0.05`, `maxPhi = PI/2 - 0.05`.
  Камеру нельзя увести под "плоскость эклиптики" — система всегда рассматривается сверху,
  как макет на столе. Верхняя граница чуть меньше `PI/2`, чтобы не смотреть строго в упор
  на плоскость (плоские объекты вырождаются в линию на экране).
- **Планета** — полная сфера: `minPhi = 0.05`, `maxPhi = PI - 0.05`. Планету можно облететь
  полностью, границы только у самых полюсов — избегаем `phi = 0`/`PI` (в этих точках
  `lookAt` с `worldUp = [0,1,0]` вырождается: forward-вектор совпадает с `up`).
- **Меню** — камера не управляется игроком: `theta` крутится автоматически (`theta += k*dt`),
  `phi`/`radius` фиксированы. Ограничители те же, что у солнечной системы (фон меню — это она
  же), просто input в это состояние не передаётся.

Смена ограничителей не телепортирует камеру — если текущий `phi`/`radius` выходят за новые
границы, они просто зажимаются (`clamp`) на следующем кадре, так что переход выглядит как
плавный доворот, а не скачок.

## Ввод

`input.js` переводит pointer-drag в дельты `theta`/`phi` (по X/Y соответственно), wheel/pinch
— в дельту `radius`. `camera.js` зажимает результат по текущим constraints каждый кадр —
никакой отдельной "анимации отскока" от границы не нужно, clamp сам создаёт ощущение упора.

## Пикинг без обратной матрицы

Для клика по сфере в 3D нужен луч (origin, direction) из курсора в мировое пространство.
Стандартный путь — unproject через обратную view-projection матрицу, но это лишний код
(инверсия mat4 ~30 строк). Вместо этого луч строится прямо из базиса камеры и FOV:

```
forward = normalize(target - eye)
right   = normalize(cross(forward, worldUp))
up      = cross(right, forward)

ndcX, ndcY — координаты клика в [-1, 1]
halfH = tan(fov / 2)
halfW = halfH * aspect

dir = normalize(forward + right * ndcX * halfW + up * ndcY * halfH)
```

Дальше — обычное пересечение луча (`eye`, `dir`) со сферами сущностей (классическая формула
через дискриминант), см. `PickEntity` в `entities.js`. Работает только потому, что камера
всегда смотрит точно на `target` (честный orbit-look-at, без произвольного наклона) — если
камера когда-нибудь станет свободной (6DOF), этот хак придётся заменить на unproject.
