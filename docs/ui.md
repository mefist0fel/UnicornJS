# UI: панели и кнопки

## Хак: DOM-оверлей поверх WebGL-канваса, а не рисование в GL

В прошлом проекте (js13k_city) UI рисовался прямо в 2D-canvas тем же кодом, что и "3D"
(`fillText`/`fillRect` с ручным пересчётом координат в пиксели каждый кадр, immediate-mode
кнопка `button(text,x,y,w,h)`, которая сама себя рисует и сама себя проверяет на клик). Там
это было оправдано — рендер и так шёл через `CanvasRenderingContext2D`, текст был "бесплатным".

Здесь рендер — WebGL. Рисовать текст в WebGL — это либо растеризация шрифта в текстуру
вручную, либо генерация геометрии букв — заметно больше кода и байт, чем нужно для двух типов
виджетов. Вместо этого:

- 3D-сцена рендерится в `<canvas>` через WebGL.
- Поверх канваса лежит обычный DOM-слой (`<div id="ui">`), абсолютно спозиционированный,
  `pointer-events: none` на контейнере и `pointer-events: auto` на самих виджетах (чтобы
  клики мимо панелей проходили сквозь на канвас — там свой пикинг по сферам).
- Панель/кнопка — это просто `<div>`, текст и раскладка — обычный HTML/CSS. Никакого JS для
  измерения текста, переносов строк, кернинга и т.п. — это всё уже умеет браузер.

Стоимость хака: немного CSS в `<head>` и обязательный `pointer-events` трюк. Выигрыш —
весь текстовый рендеринг и лэйаут не пишется руками и не занимает байты в JS-бандле.

## Относительные размеры — `vmin`, без JS

В js13k_city относительный размер считался в JS каждый кадр (`screenScale = min(w,h) * 0.01`,
все координаты кнопок/текста умножались на него). Здесь то же самое — но бесплатно, через CSS
`vmin` (1vmin = 1% от меньшей стороны вьюпорта). JS не пересчитывает ничего при resize —
браузер делает это сам.

```css
.panel  { padding: 2vmin 3vmin; font-size: 3vmin; border-radius: 1vmin; }
.button { padding: 1.5vmin 3vmin; font-size: 2.5vmin; }
```

## Два виджета — и ничего сверх

Ровно то, что нужно прототипу:

- **Текстовая панель** — `CreatePanel(text, anchor)`: div с классом `.panel`, показывает
  текст (заголовок, имя планеты и т.п.). Не кликабельна.
- **Кнопка** — `CreateButton(text, anchor, onClick)`: div/`<button>` с классом `.button`,
  вызывает `onClick` по `click`.

`anchor` — просто CSS-класс позиционирования (`top`, `bottom`, `center` — flex-контейнер на
`#ui` с `justify-content`/`align-items`), а не пиксельные/vmin-координаты в JS. Это ещё
меньше кода: раскладка — забота CSS flexbox, не наша.

## Жизненный цикл панелей

`setState` при входе в состояние вызывает `ClearUI()` (удаляет детей `#ui`), затем создаёт
нужные для этого состояния панели/кнопки. Никакого reuse/pooling виджетов — на масштабе
"меню + пара кнопок на сцену" это не стоит усложнения, а `innerHTML = ''` дешевле в коде, чем
diff/reconciliation.
