# UI: панели и кнопки

## Хак: DOM-оверлей поверх WebGL-канваса, а не рисование в GL

В прошлом проекте (js13k_city) UI рисовался прямо в 2D-canvas тем же кодом, что и "3D"
(`fillText`/`fillRect` с ручным пересчётом координат в пиксели каждый кадр, immediate-mode
кнопка `button(text,x,y,w,h)`, которая сама себя рисует и сама себя проверяет на клик). Там
это было оправдано — рендер и так шёл через `CanvasRenderingContext2D`, текст был "бесплатным".

Здесь рендер — WebGL. Рисовать текст в WebGL — это либо растеризация шрифта в текстуру
вручную, либо генерация геометрии букв — заметно больше кода и байт, чем нужно для двух типов
виджетов. Вместо этого:

- 3D-сцена рендерится в `<canvas>` через WebGL.
- Поверх канваса лежит обычный DOM-слой (`<div id="ui">`), абсолютно спозиционированный,
  `pointer-events: none` на контейнере и `pointer-events: auto` на самих виджетах (чтобы
  клики мимо панелей проходили сквозь на канвас — там свой пикинг по сферам).
- Панель/кнопка — это просто `<div>`, текст и раскладка — обычный HTML/CSS. Никакого JS для
  измерения текста, переносов строк, кернинга и т.п. — это всё уже умеет браузер.

Стоимость хака: немного CSS в `<head>` и обязательный `pointer-events` трюк. Выигрыш —
весь текстовый рендеринг и лэйаут не пишется руками и не занимает байты в JS-бандле.

## Относительные размеры — `vmin`, без JS

В js13k_city относительный размер считался в JS каждый кадр (`screenScale = min(w,h) * 0.01`,
все координаты кнопок/текста умножались на него). Здесь то же самое — но бесплатно, через CSS
`vmin` (1vmin = 1% от меньшей стороны вьюпорта). JS не пересчитывает ничего при resize —
браузер делает это сам.

```css
.panel  { padding: 2vmin 3vmin; font-size: 3vmin; border-radius: 1vmin; }
.button { padding: 1.5vmin 3vmin; font-size: 2.5vmin; }
```

## Три виджета — и ничего сверх

Ровно то, что нужно прототипу (третий, `.bar`, добавлен под HP/энергию боя — см. ниже, это
не общий "виджет на будущее", а конкретная нужда `battle_state.js`):

- **Текстовая панель** — `CreatePanel(text, anchor)`: div с классом `.panel`, показывает
  текст (заголовок, имя планеты и т.п.). Не кликабельна.
- **Кнопка** — `CreateButton(text, anchor, onClick)`: div/`<button>` с классом `.button`,
  вызывает `onClick` по `click`.
- **Fill-бар** — `CreateBar(anchor, color)`: div `.bar` с внутренним `<i>`, растущим от низа
  (`bottom:0; height: pct%`). `.set(pct)` (0..100) двигает заливку. `ship_state.js` рисует им
  HP корабля и HP текущей цели (`barsright`, второй сдвинут по `style.right`). Как и
  панель/кнопка, раскладка — CSS (`vmin`), JS ничего не пересчитывает кроме `%`.

## Редактор слотов — секционный список фиксированных блоков (`ship_state.js`)

Слева (anchor `leftcol`, `left:2vmin`) — секции: строка **Ship** (апгрейд фрейма), затем
заголовок `WEAPONS N/потолок` + активные оружейные слоты, так же `MODULES`, `SUPPORT`
(`ShipModuleList()` в `modules.js` отдаёт готовые строки). При выборе строки в колонке 2
(anchor `leftcol2`, `left:19vmin`) появляется список конверсий с ценой в металле; постройка
**или повторный клик** по выбранной строке колонку 2 закрывают (`selected` → `-1`).

Ключевой момент — **блоки фиксированного размера**: класс `.slotbtn` задаёт
`box-sizing:border-box; width:16vmin; height:3vmin` (заголовки — `.slothdr`, `height:2.4vmin`),
и они лежат в таблице стилей **после** `.button`/`.panel`, иначе базовые правила (жирный
`padding`/`font-size` кнопки) перебили бы их по каскаду. Раскладка — ручной бегущий `y`
(`y += 3.2` на строку, `2.6` на заголовок): раз высота предсказуема, N кнопок гарантированно
влезают подряд без наложения. `leftcol`/`leftcol2` — anchor-классы (`top:0; transform:none`),
не новый тип виджета. Заголовки секций строятся через `CreatePanel`, но className сразу
перезаписывается на `'leftcol slothdr'` (без `panel`).

Выбор слота дублируется 3D-пикингом по кубику **построенного** модуля (`selectSlot(i)` из его
`onClick`); у пустых слотов 3D-визуализации нет вообще.

## Дебаг-меню (`debug.js`)

`CreateDebugMenu(extra)` — маленькая кнопка `D` в углу (anchor `dbg`, `left:2vmin; top:2vmin`),
клик разворачивает/сворачивает столбец кнопок-команд `[...DEBUG_GLOBAL, ...extra]`, каждая —
`{ label, run }`. `DEBUG_GLOBAL` (`+50 Metal`, `+10 Fuel`) — всегда; состояние докидывает своё
(`ship_state.js` передаёт замыкания `Spawn <name>` на `spawnEnemy`). Открытый столбец лежит
поверх редактора слотов (непрозрачный фон) — это дебаг-инструмент, сосуществование с
редактированием не требуется. Всё — обычные `.button`, так что `ClearUI()` на `SetState` их
сносит как любой виджет. Добавить команду = добавить одну запись `{label, run}`.

## Hold-кнопка — тот же виджет, другое событие

`CreateHoldButton(text, anchor, onDown, onUp)` — не новый тип виджета, а `CreateButton` с
другой проводкой событий: `pointerdown` вместо `click` включает эффект, `pointerup` **и**
`pointerleave`/`pointercancel` выключают. Сейчас в игре **не используется** (остался с
hold-based боя, см. [battle.md](battle.md) — вариант A); держим на случай возврата к
зажимаемым способностям.

`anchor` — просто CSS-класс позиционирования (`top`, `bottom`, `center`, `bottomleft`,
`bottomright`, `dbg` — каждый на `#ui` задаёт `position:absolute` в нужном углу/крае через
голый CSS), а не пиксельные/vmin-координаты в JS. Раскладка — забота CSS.

**Конвенция низа экрана:** пассивное действие — `bottomleft`, активное (тратит ресурс /
двигает игрока / необратимо) — `bottomright`. Так: `Map`, `Return to ship` — слева; `Jump`,
гиперпрыжок `>` — справа.

**Прогресс сборки** (`ship_state.js` + `PendingBuild` в `modules.js`): пока слот строится,
его строка в списке показывает `имя ▸Ns` и фон `linear-gradient` по `frac` вместо выделения;
клик по такой строке игнорируется, `col2` не открывается.

## Больше одного виджета в одном anchor — ручной сдвиг

Anchor-классы центрируют/прижимают **весь** ряд как одно целое — второй элемент с тем же
классом просто ляжет поверх первого, а не встанет рядом. Для прототипа этого достаточно почти
везде (на экран редко нужно больше одной панели+кнопки на угол), кроме диалога: там до 4
кнопок выбора плюс строка текста, все снизу. Заводить под это отдельный виджет-список — лишнее
ради одного экрана, поэтому `dialog_state.js` вместо этого руками сдвигает каждый элемент по
`style.bottom` после создания:

```js
const btn = CreateButton(label, 'bottom', onClick)
btn.style.bottom = (4 + i * 6) + 'vmin'   // i-я кнопка снизу вверх, 6vmin друг от друга
```

Это хак ровно под один экран с известным малым числом кнопок (≤4) — не общий механизм
раскладки. Если понадобится больше одного места с несколькими элементами в одном углу, тогда
стоит завести настоящий anchor-контейнер со своим flex/gap в CSS, а не размножать этот приём.

Горизонтальный вариант того же приёма (`btn.style.left = 'calc(50% + Nvmin)'`, инлайновый
`left` перебивает `left:50%` из `#ui>*`, а `transform:translateX(-50%)` из той же таблицы
остаётся и центрирует кнопку уже относительно нового `left`) сейчас в игре не нужен — держим
описание на случай возврата к ряду кнопок в одном anchor'е.

Второй бар в паре (`ship_state.js` — HP цели рядом с HP корабля на `barsright`) сдвинут
`el.style.right` вместо CSS, чтобы встать рядом, не поверх.

## HUD ресурсов — постоянная панель вне #ui

Ресурсы игрока (`resources.js`) показываются одной строкой в правом верхнем углу **всегда**,
независимо от текущего состояния — а `ClearUI()` при каждом `SetState` чистит `#ui` целиком
(см. "Жизненный цикл панелей" ниже). Городить исключение в `ClearUI()` или пересоздавать
HUD-панель в каждом из 9 состояний — лишний код на обе стороны. Вместо этого HUD живёт в
отдельном контейнере `#hud`, соседнем с `#ui` в разметке, а не внутри него — `SetState` его
никогда не трогает. `resources.js` сам инициализирует и обновляет свой единственный div
(`RenderResHud()`), без похода через `CreatePanel`/`ClearUI` вообще — у HUD другой жизненный
цикл (живёт всю игру, обновляется по изменению ресурса, а не по смене сцены), поэтому он не
влезает в рамки виджета `.panel`, даже визуально с ним похожий.

## Жизненный цикл панелей

`setState` при входе в состояние вызывает `ClearUI()` (удаляет детей `#ui`), затем создаёт
нужные для этого состояния панели/кнопки. Никакого reuse/pooling виджетов — на масштабе
"меню + пара кнопок на сцену" это не стоит усложнения, а `innerHTML = ''` дешевле в коде, чем
diff/reconciliation.
